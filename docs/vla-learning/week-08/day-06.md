## 1. 今日目标与预计时间

预计 120 分钟。建立从数据到执行的分层调试矩阵，并主动注入时间错位、颜色通道、文本错配、动作尺度和 success checker 五类故障，验证监控能定位它们。

## 2. 这在 VLA 中的作用

端到端失败可能来自感知、语言、融合、动作、控制或评估。直接换模型会把系统错误掩盖为“模型能力不足”；故障注入能证明你的检查真正有效。

## 3. 核心概念与诊断顺序

建议按可观测边界调试：

```text
1 数据/schema/时间
2 单模态预处理与编码
3 跨模态配对/grounding
4 normalized action 与 loss
5 denormalize/坐标/安全层
6 env transition/control
7 success/metrics/reporting
```

每层记录：假设、最小输入、预期不变量、观测证据、结论。不要以“训练 loss 下降”跳过前五层。

## 4. 分步学习

1. 为七层各列至少两个自动检查和一个人工可视化/抽查。
2. 注入 `action_{t+1}` 错位，观察时间对齐/回放检查是否报错。
3. 注入 RGB↔BGR 或图像翻转，观察预处理/探针指标。
4. 跨 episode 打乱文本，观察 paired grounding 检查与成功率。
5. 将动作反归一化重复一次或漏一次，观察范围/首步轨迹。
6. 放宽 success 条件制造假成功，确认阶段谓词/负向序列抓住。
7. 对每个故障记录“首个能检测到的层”，避免依靠最终失败猜测。

## 5. 必做作业

- 提交七层诊断矩阵。
- 实际完成五类故障注入；每类保留未注入/注入后的日志差异。
- 选一个真实 rollout 失败，按矩阵从上到下定位，给出最小可证伪下一步。

## 6. 输入、预期输出与验证

输入：一个已知正常 synthetic batch、一个可回放 episode、Day 5 rollout 脚本；所有注入只在副本/测试开关中进行。

预期输出：五类故障至少各被一个预期检查捕获，并能指出首个异常边界；原始数据/checkpoint 未被修改。均为预期结果。

验证：关闭注入后测试恢复通过；注入开关写入日志；检测器不仅看到最终 success 下降，还报告具体不变量；对 checker 自身加入负向测试。

## 7. 固定提交格式

```markdown

## 七层诊断矩阵
## 五类故障注入设置
## 注入前后日志/指标对照

## 一个真实失败的逐层定位
## 自测答案
```

## 8. 评分与验收

- 七层矩阵具体可执行：20 分。
- 五类注入安全且可关闭：20 分。
- 检测日志能定位而非只报失败：25 分。
- 真实失败逐层证据：20 分。
- 恢复验证、自测和数据保护：15 分。

总分 100，80 分通过；修改原始数据、只凭最终成功率定位或检测器无法区分至少三类故障时不通过。

## 9. 常见错误与排查

| 错误 | 排查 |
|---|---|
| 同时注入多个故障 | 每次只改一个变量并保留 control |
| 注入后忘记关闭 | 配置显式标记并在正式评估拒绝 debug 模式 |
| 只看均值掩盖首帧异常 | 保存逐步日志和首个越界时间 |
| 成功判定器自己有 bug | 用 Day 5 合成序列先单测 checker |

## 10. 时间不足时的最低完成线

CPU Mock 完成时间错位、文本打乱、动作重复反归一化三类注入，以及七层简化诊断矩阵。

## 11. 可选提高

把检查整合为 preflight 命令；生成 failure bundle；增加相机外参和控制延迟注入。
