## 1. 今日目标与预计时间

预计 90–120 分钟。完成一份可审计的平台决策，并让一个环境完成 `reset → 10 次 step → close`。平台可选 ManiSkill、Isaac Lab、RLBench；若当前机器无法运行，则先用 NumPy Mock 保持接口一致。

## 2. 这在 VLA 中的作用

仿真平台决定传感器、动作频率、坐标约定、任务判定和数据格式。选择错误不是“以后换环境”这么简单，它会渗透到训练标签与评估协议。Mock 的意义是先固定契约，让后续数据和模型工作不被 GPU 或安装阻塞。

## 3. 核心概念、公式与数据流

平台决策至少比较：操作任务覆盖、API 稳定性、渲染后端、GPU/驱动要求、已有专家数据、许可证和复现成本。

统一环境契约：

```text
seed + task_config
      ↓
env.reset() → obs_0, info_0
      ↓ action_t
env.step(action_t) → obs_{t+1}, reward_t, terminated, truncated, info
```

低资源 Mock 可用二维状态 `s_t=[gripper_x, gripper_y, object_x, object_y, closed]`，动作 `a_t=[Δx, Δy, gripper_cmd]`，形状分别为 `[5]` 与 `[3]`。状态转移可写为 `p_{t+1}=clip(p_t+Δp, low, high)`。

## 4. 分步学习

1. 记录 CPU、内存、GPU/显存、操作系统和现有 Python 版本，不安装新包。
2. 用矩阵给三个平台在任务覆盖、资源、安装成本、相机支持和数据导出上各打 1–5 分，并写评分依据。
3. 选择主路径和降级路径；主路径未安装时不要联网安装，直接执行 Mock。
4. 定义 `reset(seed)`、`step(action)`、`render()`、`close()` 的最小接口。
5. 固定 seed 运行两次 10 步动作序列，比较初始状态与最终状态是否一致。

## 6. 输入、预期输出与验证

输入：固定 `seed=7`；动作序列为 10 个 `[0.01, 0.00, 0]`；Mock 边界可设为 `[-1,1]`。

预期输出：两次运行的 `obs_0` 和最终 `state` 完全一致；每次 `step` 返回 5 个逻辑结果；日志显示状态 shape `[5]`、动作 shape `[3]`。这是预期结果，需用实际输出验证。

验证：用 `np.testing.assert_allclose(run1, run2)`；断言字段齐全、数值有限、动作不修改输入数组；程序退出码为 0。

## 9. 常见错误与排查

| 错误 | 排查 |
|---|---|
| 把“文档支持”当成本机可运行 | 只记录实际 import 与 smoke test 证据 |
| 两次 seed 仍不一致 | 同时固定环境、NumPy 和动作序列，检查渲染噪声 |
| `step` 返回结构混乱 | 用命名字段或固定五元组并写类型断言 |
| Mock 与真实平台接口分叉 | 用 adapter 保持同一 observation/action schema |

## 10. 时间不足时的最低完成线
