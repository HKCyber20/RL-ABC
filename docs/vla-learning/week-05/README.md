## 本周核心能力

本周把前四周学到的动作、坐标系、时间对齐和行为克隆概念落到一个可运行的环境契约上。完成后，你应能选择或模拟一个抓取放置平台，明确 `reset/step` 接口、观测与动作空间、相机标定、成功条件，并采集可验证、可回放的轨迹。这是总 Goal 中“构造图像 + 语言 + 机器人状态 → 动作数据”的入口。

## 前置知识

- 能读写 Python、NumPy 数组和 JSON/NPZ 文件。
- 理解 `image_t/state_t/action_t` 的时间对齐。
- 能区分绝对动作与增量动作，并写清坐标系和单位。
- 知道 rollout、episode、terminal 与 success 的基本含义。

## 本周代码与实验产物

- `platform_decision.md`：平台、版本、硬件成本和降级路径。
- `env_smoke_test.py`：固定 seed 的 `reset/step` 最小测试。
- `trajectory_schema.md`：字段、形状、dtype、单位、坐标系和时间语义。
- `success.py`：任务成功与阶段指标判定器。
- 一份成功/失败混合的小数据集，以及 `manifest.json`。
- `replay_check.py` 与回放报告，能够定位首个不一致时间步。

课程不预设这些脚本已运行；文中出现的数值均标作“预期结果”，必须由你的实际日志替换或佐证。

## 必做与可选

必做：完成 7 天核心作业；至少用真实仿真平台采集 20 条成功轨迹，或用 CPU Mock 生成 5 条确定性轨迹并完成同一套 schema、回放和校验。

可选：增加腕部相机、深度图、人工遥操作、数据压缩比较，或把采集规模扩展到 100 条成功轨迹。

## 最低完成线

用纯 NumPy Mock 环境完成 Day 1、2、3、5、7；保存至少 5 条 episode，其中至少 3 条成功、1 条故意失败；逐步回放并验证状态转移、动作边界和成功标签。最低完成线不允许省略坐标系、单位与时间戳说明。

## 周末测验

闭卷回答：`terminated` 与 `truncated` 的差异；为何成功标签不能只看最后一帧；相机外参的方向；动作标签为何通常对应 `obs_t` 之后执行的 `action_t`；离线文件可读为何仍不足以证明可回放。

## 周项目

构建“抓取红色方块并放入目标区域”的可回放数据管线。真实平台路径应保存至少 20 条成功轨迹；低资源路径使用二维点夹爪 + 方块的确定性 Mock。两条路径采用统一逻辑字段：`rgb/state/action/instruction/timestamp/terminated/truncated/success`。

## 通过标准

- 7 个日课总评均达到各自通过线，Day 7 周项目达到 80/100。
- schema 明确每个字段的形状、dtype、单位、坐标系、频率和时间语义。
- 至少一条轨迹能从磁盘读取并逐步回放；状态与奖励/成功标签一致。
- 能展示成功与失败样本，并说明失败发生在感知、策略、控制还是数据层。
- 真实仿真器不可用时，有可复跑的 CPU Mock 证据，而不是口头声称“已跑通”。
