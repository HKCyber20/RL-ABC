## 1. 今日目标与预计时间

预计 2–3 小时。把轨迹整理为带 manifest、schema 版本和校验和的数据集，完成逐步回放、一致性检查与本周闭卷测验。

## 2. 这在 VLA 中的作用

“文件能打开”不等于数据可训练。可回放性证明动作、状态转移、终止与成功标签自洽；manifest 让未来的训练、切分和复现实验能追溯到同一批数据。

## 3. 核心概念、公式与数据流

建议目录：

```text
dataset/
├── manifest.json
├── schema.json
└── episodes/episode_000001.npz
```

manifest 至少含 `dataset_id/schema_version/platform/task/episode_count/success_count/action_spec/camera_spec/created_by`。确定性 Mock 可验证：

\[
\max_t\|\hat s_{t+1}-s_{t+1}\|_\infty < \epsilon.
\]

真实物理仿真若非完全确定，应比较任务阶段、末端轨迹误差和最终 success，并记录容差。

## 4. 分步学习

1. 选择 NPZ/HDF5/其他容器并说明压缩、随机访问和依赖权衡；无需安装新包。
2. 写 manifest 和 schema 版本；逐 episode 记录长度、seed、success、终止原因。
3. 从磁盘加载随机 episode，验证 key、shape、dtype、时间戳和校验和。
4. reset 到同一 seed 后逐步执行动作，比较记录状态与重放状态。
5. 定位首个超过容差的时间步，输出字段级差异。
6. 完成周测与数据卡，报告限制和禁止用途。

## 5. 必做作业

- 提交数据集 manifest、schema、至少 5 条低资源轨迹或真实平台目标数据。
- 运行 `replay_check.py`：至少一条成功轨迹与一条失败轨迹。
- 输出数据质量报告：数量、长度分布、成功率、动作范围、同步误差、坏样本数。
- 闭卷回答本周首页列出的五个问题。

## 6. 输入、预期输出与验证

输入：Day 6 的磁盘数据、相同环境版本和 seed、动作容差 `ε`。

预期输出：Mock 重放误差接近浮点容差且终止/成功一致；真实平台误差在事先声明的容差内；篡改一条动作后检查器能报告首个不一致步。均为预期结果。

验证：先运行原数据得到通过，再复制一条内存记录并修改动作做负向测试；禁止破坏原数据。检查所有 manifest 计数与实际文件一致，随机抽样可视化不少于 3 帧。

## 8. 评分与验收

- manifest、schema 与文件计数一致：20 分。
- 成功/失败轨迹均能加载和检查：15 分。
- 逐步回放及误差定位：25 分。
- 负向测试能发现篡改：15 分。
- 数据质量报告：15 分。
- 周测与复盘：10 分。

总分 100，80 分通过；无实际回放日志、无时间/坐标语义或 manifest 与文件不一致时不通过。

## 9. 常见错误与排查

| 错误 | 排查 |
|---|---|
| 文件顺序被字典/文件系统改变 | 用显式 episode_id 与 step_index 排序 |
| replay 初始即不一致 | 检查 seed、环境版本、reset options 和随机源 |
| 压缩后 dtype 变化 | 加载后按 schema 逐字段断言 |
| 只比较最终状态 | 报告首个分叉步，避免误差抵消 |

## 10. 时间不足时的最低完成线

交付 5 条 CPU Mock 轨迹、manifest/schema、成功与失败各一条逐步回放，以及一个动作篡改负向测试。

## 11. 可选提高

为 episode 加 SHA-256；生成 HTML/GIF 回放摘要但保留原始数值检查；比较未压缩与压缩后的体积和读取吞吐。
