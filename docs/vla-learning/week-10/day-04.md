## 1. 今日目标与预计时间

预计：**100–140 分钟**。

- 验证 RGB、尺寸、值域、批维和 prompt 模板。
- 避免训练与推理预处理漂移。
- 为多相机或缺失视角设计显式策略。

## 2. 今日知识点及其在 VLA 中的作用

VLA 对预处理漂移非常敏感：颜色通道、裁剪、指令模板或相机顺序改变，都可能让接口“能运行但行为错误”。

## 3. 必要概念、公式、形状与数据流

- 原始图像通常是 uint8 [H,W,3] 或 PIL RGB；processor 输出形态依版本而异，验收应读取实际键/shape，而不是硬编码想象。
- prompt 模板属于训练分布的一部分；大小写、前后缀和空白应由一个函数生成并测试。
- 多相机输入要固定顺序与 mask；若所用模型只支持单图，不能简单在通道维拼接后声称兼容。

## 4. 分步骤学习内容

1. 编写 validate_image：mode、shape、dtype、值域、NaN/Inf。
2. 编写唯一 format_prompt(instruction) 并测试中文/英文、空白和超长输入策略。
3. 制作 train/eval preprocessing diff 表。
4. 设计多相机输入 manifest：camera name、timestamp、order、missing policy。

## 5. 必做作业

- 提交 preprocessing_contract.md 与测试。
- 构造 RGB、BGR、灰度、float 值域错和空指令 5 类样例。
- 记录 processor 真实输出 shape；若无真实 processor，写 mock 预期并明确标识。

## 6. 作业输入、预期输出与验证方法

| 项目 | 内容 |
|---|---|
| 输入 | 64×64 mock RGB、相机名 front/wrist、两条语言指令；无需真实图片下载。 |
| 预期输出 | 合法输入形成稳定 prompt 与 batch；错误输入在进入模型前失败；多相机策略不静默换序。 |
| 验证方法 | 对同一指令两次格式化结果字节一致。；随机抽样打印像素 min/max 与通道顺序证据。；检查相机 timestamp 容差有定义。 |

真实模型路径如需联网下载、安装或 GPU，必须先说明目的、磁盘/显存/时间成本并获得授权；默认完成低资源路径。

## 8. 评分与验收标准

| 评分项 | 分值 | 得分条件 |
|---|---:|---|
| 架构/公式/shape | 20 | 数据流准确，稳定概念与版本项分开 |
| 接口或配置产物 | 25 | 输入输出、异常、revision 与 key 完整 |
| 验证证据 | 25 | 命令/断言/输出可复核，mock 与 real 明确区分 |
| 动作与安全分析 | 20 | 反归一化、单位、frame、范围或 controller 风险正确 |
| 复盘与自测 | 10 | 能定位失败并回答自测 |
| **总分** | **100** | **80 分通过** |

硬门槛：BGR/RGB 未区分、prompt 在训练/推理两处各自拼接，或缺失相机静默用上一帧，不得通过。

## 9. 常见错误与排查提示

- 把 resize 后 shape 当作原始图像证据。
- float 图像 [0,255] 被再次乘 255。
- 相机排序依赖字典偶然顺序。
- 先打印输入 mode/shape、processor keys、model revision、action stats key 与 action shape，再排查数值。
- 不得声称执行过未实际运行的安装、推理或训练。
