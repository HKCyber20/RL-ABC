## 1. 今日目标与预计时间

预计：**160–230 分钟**。

- 制作不挑样本的代表性 demo。
- 完成从问题到限制的最终技术报告。
- 让复现者能从干净进程重建主要表格。

## 2. 今日知识点及其在 VLA 中的作用

demo 负责直观证据，报告负责完整证据，REPRODUCE 负责可验证性；三者互补而不能互相替代。

## 3. 必要概念、公式、形状与数据流

- demo 明确 checkpoint、seed、instruction、condition、是否成功、是否剪辑；同时展示成功与失败，避免 cherry-pick。
- 报告最小结构：摘要、任务/spec、相关工作、数据、方法、训练、评估协议、结果、泛化、失败/消融、OpenVLA 接入、限制、安全与复现。
- 复现命令分为 environment check、data validate、train/smoke、eval、report；每步给预期产物而非伪造输出。

## 4. 分步骤学习内容

1. 按预注册规则选择代表 case，不按画面好看挑选。
2. 生成视频或逐帧 Markdown；标时间/step 与动作。
3. 写 FINAL_REPORT.md，把每个数字链接到表/manifest。
4. 从新进程按 REPRODUCE.md 复跑最小路径并记录耗时。

## 5. 必做作业

- 提交 DEMO.md/视频、FINAL_REPORT.md、REPRODUCE.md 与 artifact manifest。
- 报告至少包含一张主结果表、一张失败分布、一项消融和三条限制。
- 复现日志包含命令、退出码、环境与产物 hash。

## 6. 作业输入、预期输出与验证方法

| 项目 | 内容 |
|---|---|
| 输入 | Day 1–5 冻结产物。 |
| 预期输出 | demo 同时有成功/失败；报告无孤立数字；最小复现从数据校验到结果表实际完成。 |
| 验证方法 | 逐个报告数字查数据源。；让另一人或新 shell 按命令执行。；检查链接、路径、seed 和 stats key 均明确。 |

本周“预期”不能替代最终核心闭环实测；需要大模型/GPU 的 OpenVLA 部分可用明确标注的 CPU/mock dry-run。

## 7. 提交内容与固定格式

```markdown
# W12D06 提交

- 实际用时：记录分钟数
- run/result id：记录可追踪标识
- 证据等级：真实轻量/完整仿真、真实 OpenVLA、OpenVLA mock dry-run（逐项说明）

## 冻结合同与设计
记录 spec/config/data/checkpoint hash 及关键 shape、单位和 frame。

## 实际产物
列出代码、数据、日志、报告和 demo 的绝对或仓库相对路径。

## 复现与验证证据
粘贴命令、退出码、关键输出、重算/重播证据；未执行项明确写“预期”。

## 失败、限制与补救
区分观察、推断和假设，给最小补救验收标准。

## 自测/答辩答案
逐题作答。
```

## 8. 评分与验收标准

| 评分项 | 分值 | 得分条件 |
|---|---:|---|
| spec/概念/shape | 20 | 输入、动作、闭环和版本合同准确 |
| 实际项目产物 | 25 | 文件完整，来源与 hash 可追踪 |
| 复现与验证 | 25 | 实际命令、退出码、重跑/重算证据充分 |
| 泛化/失败/OpenVLA | 20 | 证据边界清楚，能诊断并解释接入 |
| 复盘与答辩 | 10 | 限制诚实，回答自测并给补救 |
| **总分** | **100** | **80 分通过** |

硬门槛：只展示精选成功、报告数字不可追踪，或复现说明依赖未记录的手工步骤，不得通过。

## 9. 常见错误与排查提示

- 视频没有指令/condition 标签。
- 绝对本机路径写死。
- 未运行的命令写成已成功。
- 先核对 spec/config/data/checkpoint/result hash、seed、stats key、动作单位/frame，再解释性能。
- 不得把手写 outcome、mock OpenVLA 输出或预期命令包装成真实闭环/模型结果。

## 10. 时间不足时的最低完成线

一段成功+一段失败帧序列、完整报告骨架与实际最小复现日志。 最低完成线仍须满足当天硬门槛。
