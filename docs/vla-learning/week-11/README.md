## 本周核心能力与总 Goal 中的作用

**核心能力：**能设计无泄漏的 ID/OOD 评估矩阵，用多 seed 成功率与不确定性汇报结果，分别测试未见位置、未见组合和背景干扰，并以可复核 taxonomy 将失败定位到数据、感知、语言、控制或终止阶段。

最终 Goal 不只是训练策略，而是证明策略在什么条件下可靠、为什么失败以及哪些改动有效。本周产物将直接成为最终报告的评估与失败分析章节。

## 前置知识

- 已有可 rollout 的语言条件策略；若仿真不可用，可用固定格式的历史/mock rollout 日志完成分析流程。
- 会定义任务成功条件、固定随机种子并记录 episode 元数据。
- 理解训练/验证/测试泄漏、混杂变量与基本比例统计。

## 本周代码与实验产物

- eval_matrix.yaml/md：因素、水平、split、seed、episode 数与成功判据。
- success_ci.py：成功率、Wilson 区间和按 seed 汇总。
- unseen_position_report.md、compositional_report.md、background_robustness.md。
- failure_taxonomy.yaml 与逐 episode 标注表。
- ablation_table.csv/md、w11_evaluation_report.md 和可复跑命令。

## 必做任务

- 主结论必须至少 3 个 seed，若资源不足则报告实际 seed 数并降级为探索性，不虚构。
- 成功率分母、重试规则、最大步数和超时/异常如何计数必须冻结。
- 每个 OOD 测试只改变声明的因素，或显式记录未能控制的混杂变量。
- 失败类别有互斥的主因规则、可选次因和证据字段。

## 可选任务

- 做 paired-seed 或 bootstrap 敏感性分析。
- 加入动作平滑度、完成时间、碰撞率和校准指标。
- 对 taxonomy 做双人/重复标注一致性检查。

## 时间不足时的最低完成线

不运行新仿真也可：构造或使用至少 30 条带 seed/condition/outcome 的明示 mock 日志，完成评估矩阵、CI 脚本、三个泛化切片、失败 taxonomy 和一项消融；所有 mock 结论只用于验证分析管线。

## 周末概念测验

1. 为什么仅比较训练 loss 不能回答闭环泛化？
2. Wilson 区间比 p±标准误的朴素区间在小样本/极端比例时有什么优势？
3. 设计未见位置 split 时如何防止边界泄漏？
4. 一个 episode 同时抓空和超时，怎样选择主失败原因？

闭卷 80 分通过。split 泄漏、成功率分母和失败主因规则属于硬门槛，必须补救后复验。

## 周项目

用同一冻结 checkpoint/策略配置对 ID、未见位置、未见组合、背景干扰组成的评估矩阵做多 seed 分析；输出成功率与区间、失败分布、至少一项消融和三条有证据的改进建议。资源不足时用明确标注的 mock 日志验收分析代码，不宣称策略性能。

## 本周通过标准

- 7 个日课均达到 80/100，且 split、分母和失败分类硬门槛通过。
- 报告中每个数都能追溯到 episode id、seed、condition、checkpoint/config hash。
- 至少三条泛化轴分别报告，不以总体平均掩盖最差切片。
- 完成一项只改变一个因素的消融；结论区分观察、推断和尚未验证的假设。

只能用证据更新进度；探索性/模拟分析与真实策略评估必须分开呈现。
