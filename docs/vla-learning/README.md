# VLA 12 周完整课程

> **总 Goal**：在 12 周内完成一个可复现的仿真 VLA 项目：能够构造“图像 + 语言 + 机器人状态 → 动作”的数据，训练和闭环评估语言条件机器人策略，分析泛化与失败案例，并理解及运行 OpenVLA 的推理/小规模适配流程。

## 课程定位

这是一套以证据验收为核心的 84 天课程。课程文件会预先提供全部知识点和作业，但学习进度只在提交证据并通过对应 rubric 后更新。

原有的总体路线仍保留在 [VLA 学习计划](../VLA学习计划.md)；本目录将其展开为逐日可执行课程。若两者的粒度不同，以本课程对应日课的验收标准为准。

## 使用方法

每天按照以下闭环推进：

```text
阅读当天课程
   ↓
完成必做作业
   ↓
按统一模板提交代码、日志、图表或答案
   ↓
依据 rubric 逐项验收
   ├── 未通过：完成最小补救任务，保持未完成
   └── 通过：更新 PROGRESS.md，进入下一天
```

1. 从 [Week 01 / Day 01 课程](week-01/day-01.md) 开始学习。
2. 打开对应的 [Week 01 / Day 01 Notebook](notebooks/week-01/day-01.ipynb)，直接在独立 Markdown/Code 单元中填写答案和证据。
3. 所有 84 份 Notebook 都可从 [Notebook 作业总览](notebooks/README.md) 进入；旧 Markdown 作业仅保留为迁移备份。
4. 将保存后的 Notebook 路径发到当前对话，不要自行勾选进度。
5. 教练验收通过后才更新 [进度看板](PROGRESS.md)。
6. 每周 Day 07 包含周测、代码复跑和周项目验收；未通过周验收不能进入下一周。

## 验收约定

- 每日作业采用 100 分 rubric，默认达到 80 分且所有“门槛项”通过才算完成。
- 仅口头声称“完成”不构成证据；需要提交答案、代码路径、命令、关键日志、图表或录屏截图之一。
- 未实际执行的输出必须标记为“预期结果”，不能作为运行证据。
- 代码任务要检查输入、输出、张量形状、数值范围和至少一个失败分支。
- 涉及机器人任务时，要明确坐标系、单位、时间对齐、动作定义和控制频率。
- 涉及策略质量时，优先使用闭环成功率和失败分类，不用训练 loss 代替任务指标。
- 后续可修订尚未开始的课程；已经通过的任务保留原验收记录。

## 资源等级与替代方案

| 等级 | 可用资源 | 课程执行方式 |
|---|---|---|
| L0 | 普通 CPU、无仿真器 | 使用随机张量、合成数据、mock 环境和静态接口测试 |
| L1 | 可运行轻量仿真 | 完成小规模采集、训练和闭环 rollout |
| L2 | CUDA GPU、较大磁盘 | 使用预训练视觉模型、LoRA 或 OpenVLA 实际推理 |

低资源替代用于保证学习不中断，但不能伪装成真实仿真或真机结果。最终项目仍需完成至少一个可运行的轻量仿真闭环；OpenVLA 若受硬件限制，可用接口 dry-run、动作反归一化测试和数据适配器测试作为替代证据，并在最终报告中明确限制。

## 最终通过标准

最终验收必须同时满足：

1. 数据至少包含图像、语言指令、机器人状态、动作、episode/step 边界和成功标签；
2. 能从固定配置和随机种子复现一次训练或低资源训练流程；
3. 完成语言条件策略的闭环仿真评估，ID 设置不少于 20 个 episode；
4. 至少评估两类 OOD 条件，每类不少于 20 个 episode，报告成功率和样本数；
5. 使用固定 taxonomy 标注失败案例，并给出不少于 5 个有证据的失败分析；
6. 明确记录图像预处理、坐标系、动作空间、归一化、时间对齐和控制频率；
7. OpenVLA 部分提供推理或小规模适配的运行证据；硬件不足时提供可执行 dry-run、数据适配和动作解码测试，并明确未覆盖范围；
8. README 中包含环境、数据、训练、评估命令以及预期产物路径；
9. 最终答辩能够解释 VLA、VLM、BC、cross-attention、action chunk、闭环评估及主要失败来源。
