## 1. 今日目标与预计时间

预计 2–3 小时。将坐标变换、旋转检查、动作规范和闭环频率整合为一份可复用的动作接口与验证器，完成闭卷周测。

## 2. 今日知识点及其在 VLA 中的作用

动作接口是模型与机器人之间的合同。它同时约束数据标签、模型输出、反归一化、坐标变换和控制执行；其中任一环节的约定不一致都会造成“模型数值看似正确、机器人行为错误”。

## 3. 必要概念、公式、形状与数据流

周项目数据流：

```text
normalized prediction [B,7]
 -> denormalize/clip
 -> interpret in declared frame/unit
 -> compose T / validate rotation
 -> optional IK
 -> execute at declared Hz
 -> log new state and status
```

验证器至少检查：shape/dtype/finite、范围、frame、单位、旋转合法性、夹爪集合、频率、时间戳单调性。

## 4. 分步骤学习

1. 闭卷完成六题周测并标注不确定项。
2. 整理 `ACTION_SPEC` 为版本化表格。
3. 实现 `validate_action` 和 Day 2 的变换函数。
4. 用一个合法动作和至少四个非法动作测试。
5. 输出机器可读/人可读错误信息，并写周复盘。

## 5. 必做作业

周测（30 分）：解释 `T^A_B`；写变换组合和逆；列举旋转合法性；区分 FK/IK；比较绝对/增量动作；说明 10 Hz 增量策略改到 20 Hz 的风险。

周项目（70 分）：创建动作规范与验证器。非法样例至少覆盖 NaN、越界、错误维度、未知 frame/夹爪值中的四类；演示一个相机点经两段变换到 base；提交 round-trip 误差和验证输出。此项目是纯数学接口，不声称连接真实硬件。

## 6. 输入、预期输出与验证方法

- 输入：合法 `[7]` 动作、四类非法动作、两个已知齐次变换、测试点。
- 预期：合法样例通过；非法样例分别给出明确原因；变换 round trip 误差满足阈值；动作规范字段齐全。
- 验证：从干净进程执行；所有测试都有 pass/fail；检查错误没有被静默 clip（若 clip 是策略，也要记录发生）。

低资源替代：用 Markdown 规格 + 手算变换 + 测试用例表，之后补代码才可完整通过。

## 7. 提交内容与固定格式

固定包含：`周测答案`、`ACTION_SPEC 版本`、`验证器代码/规则`、`测试矩阵`、`变换证据`、`已知限制`、`本周复盘`、`总投入时间`。

## 8. 评分与验收标准

100 分，80 分通过：周测 30；规格 20；验证器 20；变换 15；测试与错误信息 10；复盘 5。坐标方向、单位、夹爪语义、频率四项均为门槛；任一缺失不通过。

## 9. 常见错误与排查

- 规范与代码常量重复且不一致：验证器从同一规范读取。
- 对非法值全都返回 `False` 无原因：输出字段级错误。
- clip 后声称原动作合法：同时记录原值与处理值。
- round trip 只测原点：至少再测非零点。

## 10. 时间不足时的最低完成线

完成周测、完整动作规格、一个合法和两个非法验证、一个变换 round trip；其余登记为补救，整周暂不勾选。

## 11. 可选提高任务

为规格增加 JSON Schema 风格字段或单元测试参数化表，并设计版本不兼容时的拒绝机制。

## 12. 完成后的自测题

1. 能否仅凭 ACTION_SPEC 重建动作的物理含义？
2. 相机外参写反时哪个测试能最快发现？
3. 模型输出合法但 IK 失败，应归为哪类失败？
4. 哪些验证必须在每个 rollout step 执行，哪些可在初始化时执行？
