## 1. 今日目标与预计时间

预计 75–100 分钟。理解“同一个物理点在不同坐标系中数值不同”，画出机器人基座、相机、末端和物体坐标系，并建立清晰符号约定。

## 2. 今日知识点及其在 VLA 中的作用

VLA 输出的 `Δx=0.02` 若不声明参考系就无法执行：在基座 x 轴、相机 x 轴或末端自身 x 轴上可能是三个不同方向。数据混用坐标系会让同一视觉情景对应冲突标签，模型 loss 难降或闭环方向错误。

## 3. 必要概念、公式、形状与数据流

用 `{A}` 表示坐标系 A，`p^A` 表示点 p 在 A 系下的坐标。若 A 系中 B 系原点位置为 `t^A_B`，B 的朝向在 A 中为 `R^A_B`：

\[
p^A=R^A_B p^B+t^A_B
\]

形状为 `R [3,3]`、`p,t [3]`，批量时可为 `[B,3,3]` 和 `[B,3]`。常见坐标系：world、robot base、camera、end-effector/tool、object。命名必须同时表达“从谁到谁”。

## 4. 分步骤学习

1. 在一张桌面操作草图上画五个坐标系的原点和正轴。
2. 规定右手系并写明相机轴约定；不要假设所有库相同。
3. 手算二维例子：B 系相对 A 旋转 90° 且平移 `[1,0]`，把 `p^B=[1,0]` 变到 A。
4. 写出“动作在 base frame 表达”和“动作在 tool frame 表达”的不同。
5. 列出数据记录中每个位置字段必须附带的元数据。

## 5. 必做作业

画坐标系图，至少包含 `{W},{B},{C},{E},{O}`；为每个坐标系写原点、轴向来源和用途。完成上述二维变换，并设计一个反例：同一个 `[0.01,0,0]` 增量在 base 与已旋转 90° 的 tool 坐标系中导致不同世界运动。

## 6. 输入、预期输出与验证方法

- 输入：二维 `R(90°)=[[0,-1],[1,0]]`、`t=[1,0]`、`p^B=[1,0]`。
- 预期：按公式得到 `p^A=[1,1]`；反例中两个动作世界方向不同。
- 验证：画图几何检查；`R^T R=I`；所有点/动作上标和参考系描述一致。

低资源方案：纸笔即可，不需要机器人环境。

## 7. 提交内容与固定格式

固定包含：`坐标系图`、`符号约定`、`二维手算`、`base/tool 反例`、`数据元数据清单`、`投入分钟数`。

## 8. 评分与验收标准

100 分，80 分通过：坐标图 20；符号方向 20；手算 20；反例 25；元数据 15。若动作没有参考系、左右手系未声明或变换方向颠倒，关键项失败。

## 9. 常见错误与排查

- 把坐标数值当物理点本身：同一点换基后数值会变。
- `R p + t` 写成 `R(p+t)`：平移所在坐标系不同。
- 图上只写 x/y 不画正向：无法检查符号。
- 默认相机 z 轴方向：查目标系统约定；本课练习需自行明确约定。
