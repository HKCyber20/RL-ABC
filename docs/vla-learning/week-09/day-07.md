## 1. 今日目标与预计时间

预计：**150–210 分钟**。

- 把 RT-1、RT-2、OXE/RT-X 的关键决策放进同一比较框架。
- 完成跨本体 mock 数据接入审计。
- 通过概念测验、代码复跑和失败复盘。

## 2. 今日知识点及其在 VLA 中的作用

论文阅读只有转化为数据、模型和评估决策才真正服务 VLA 项目；本日把本周知识固化为第 10 周可直接使用的 adapter 契约。

## 3. 必要概念、公式与数据流

- 比较维度至少包括：输入、语言融合、动作表示、数据来源、跨本体方式、训练目标、评估泛化、算力成本和主要风险。
- 周项目证据链：`原始 mock → schema 校验 → canonical action → normalization → round-trip → report`。
- 论文声称、你的推断和本地实测必须分栏记录，避免把二手理解写成事实。

## 4. 分步骤学习内容

1. 闭卷完成 4 道周测后再查资料修正。
2. 复跑 inspector 的合法与三个损坏样例。
3. 完成论文比较矩阵，并为最终项目选出保留/不采用的设计。
4. 写失败复盘：最危险的两类数据错误、当前检测覆盖和遗留风险。

## 5. 必做作业

- 提交 `w09_paper_matrix.md` 与 `w09_week_project.md`。
- 附运行命令、退出码、关键输出和产物路径。
- 给第 10 周写一份 `openvla_adapter_handoff.md`，列出 processor 前后的字段契约。

## 6. 作业输入、预期输出与验证方法

| 项目 | 内容 |
|---|---|
| 输入 | Day 1–6 全部产物；无网络/无 GPU 即可。 |
| 预期输出 | 矩阵至少 9 个比较维度；项目能接受合法样例、拒绝 3 类坏样例；handoff 明确 image、instruction、action、dataset key 与 stats。 |
| 验证方法 | 随机抽一个 episode 手工核对检查器结论。；删除一个统计 key，确认系统显式失败而非静默选默认值。；周测达到 80%，关键概念无误。 |

预期输出只有在实际运行并保留证据后才能改写为“实测通过”。

## 7. 提交内容与固定格式

```markdown
# W09D07 提交

- 实际用时：写明分钟数
- 使用环境：写明 Python/库版本；未运行写“仅静态分析”

## 概念与推导
写出关键定义、公式推导和张量形状。

## 作业实现
列出文件路径、核心代码说明与设计选择。

## 验证证据
粘贴命令、退出码、关键输出；未执行的结果逐项标为“预期”。

## 错误注入与修正
记录至少一个失败、定位证据与修复后结果。

## 自测答案
逐题回答本页自测题。
```

## 8. 评分与验收标准

| 评分项 | 分值 | 得分条件 |
|---|---:|---|
| 概念、公式与形状 | 20 | 定义准确，变量、单位和 shape 可追踪 |
| 实现或结构化产物 | 25 | 文件完整，输入输出契约明确 |
| 验证证据 | 25 | 有命令/手算、断言、实际输出或诚实的“预期”标记 |
| VLA 场景分析 | 20 | 能联系闭环、数据或动作风险，而非复述定义 |
| 复盘与自测 | 10 | 解释失败原因并正确回答自测 |
| **总分** | **100** | **80 分通过** |

硬门槛：任何进度不能仅凭口头“完成”勾选；缺少运行证据时必须写“预期”，且项目暂不算复跑通过。

## 9. 常见错误与排查提示

- 比较矩阵只有论文摘要，没有工程选择。
- 修复坏样例时同时改了多个变量，无法定位原因。
- 把下一周尚未运行的 OpenVLA 流程写成已跑通。
- 若输出与预期不符，先打印 episode/step 索引、shape、dtype、单位和 dataset key，再检查模型。
- 不得把论文中的报告结果或本页“预期输出”写成本地实测。

## 10. 时间不足时的最低完成线

完成周测、5 维论文矩阵、一个合法/两个非法复跑和 handoff 契约。 最低完成线仍须提交证据，且只能获得“最低线通过”，后续需补齐完整产物。

## 11. 可选提高任务
