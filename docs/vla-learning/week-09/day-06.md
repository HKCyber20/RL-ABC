## 1. 今日目标与预计时间

预计：**120–160 分钟**。

- 把本周 schema、时序与动作契约实现为自动检查器。
- 输出机器可读与人可读的审计报告。
- 证明检查器能抓住多个故障，而非只跑通正常样例。

## 2. 今日知识点及其在 VLA 中的作用

真实 OXE 下载昂贵且环境复杂；mock inspector 让你先验证最危险的数据逻辑，再决定是否投入下载和 GPU 资源。

## 3. 必要概念、公式与数据流

- 检查层次：文件/解析 → episode 边界 → step 字段 → dtype/shape → finite/range → 时间对齐 → action contract → 汇总统计。
- 建议错误结构：`{episode_id, step_index, code, severity, message}`，便于统计而不是解析自由文本。
- shape 示例：image metadata `[3,64,64]`、state `[8]`、action `[7]`；实际像素可省略，用校验元数据完成 CPU 静态练习。

## 4. 分步骤学习内容

1. 整合 Day 4/5 的 mock 与转换函数。
2. 实现不少于 8 条检查规则并为每条分配错误码。
3. 构造合法样例与至少 3 个坏样例：NaN、动作维度错、末步 action 非空。
4. 运行检查器，生成按错误码计数的 Markdown 报告。

## 5. 必做作业

- 提交 `inspect_rlds_mock.py`、合法/损坏样例与 `inspector_report.md`。
- 提供一条 CPU 运行命令和退出码约定：全通过为 0，发现 error 为非 0。
- 写 150 字说明哪些问题 mock 无法验证。

## 6. 作业输入、预期输出与验证方法

| 项目 | 内容 |
|---|---|
| 输入 | 前两天构造的 JSON；不要求 TensorFlow、TFDS 或真实图像。 |
| 预期输出 | 合法样例 0 个 error；每个坏样例被准确定位；报告包含 episode/step 数、形状分布、动作范围和错误码计数。 |
| 验证方法 | 复跑两次输出稳定。；对每个故障做“注入—检测—修复—再检测”。；检查报告中的计数与输入样例一致。 |

预期输出只有在实际运行并保留证据后才能改写为“实测通过”。

记录至少一个失败、定位证据与修复后结果。

## 8. 评分与验收标准

| 评分项 | 分值 | 得分条件 |
|---|---:|---|
| 概念、公式与形状 | 20 | 定义准确，变量、单位和 shape 可追踪 |
| 实现或结构化产物 | 25 | 文件完整，输入输出契约明确 |
| 验证证据 | 25 | 有命令/手算、断言、实际输出或诚实的“预期”标记 |
| VLA 场景分析 | 20 | 能联系闭环、数据或动作风险，而非复述定义 |
| 复盘与自测 | 10 | 解释失败原因并正确回答自测 |
| **总分** | **100** | **80 分通过** |

硬门槛：只打印异常但退出码始终为 0，或没有坏样例证据，不得通过。

## 9. 常见错误与排查提示

- 用字符串 `"NaN"` 代替真正的非有限数测试却未说明。
- 检查器遇第一个错误就退出，遗漏批量问题。
- 默认补齐缺字段，掩盖坏数据。
- 若输出与预期不符，先打印 episode/step 索引、shape、dtype、单位和 dataset key，再检查模型。
- 不得把论文中的报告结果或本页“预期输出”写成本地实测。

## 10. 时间不足时的最低完成线

实现 5 条规则，接受 1 个合法 episode、拒绝 2 个坏 episode，并附实际或明确标注为预期的输出。 最低完成线仍须提交证据，且只能获得“最低线通过”，后续需补齐完整产物。
