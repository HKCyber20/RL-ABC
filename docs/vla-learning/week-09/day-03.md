## 1. 今日目标与预计时间

预计：**90–120 分钟**。

- 理解 OXE 解决的数据规模与多样性问题。
- 列举跨数据集相机、状态、动作、频率和任务语义差异。
- 制作可用于接入评审的 dataset card。

## 2. 今日知识点及其在 VLA 中的作用

通用 VLA 的能力很大程度来自多源数据；能审计异构性，才不会把“轨迹更多”误当作“监督一致”。

## 3. 必要概念、公式与数据流

- OXE 是多个机器人数据集的混合生态；课程不依赖具体数据集数量，因为版本和子集会变化，需以所用 manifest 为准。
- 一个 episode 常含 `steps`，每步可能有多相机 observation、语言任务、proprioception、原始 action 和边界标志。
- 混合前至少核对：本体、控制模式、坐标系、单位、频率、相机命名、图像编码、动作维度、终止定义、许可与来源。

## 4. 分步骤学习内容

1. 绘制两个虚拟本体 A/B 的原始字段表。
2. 标记哪些字段能直接合并、哪些需转换、哪些必须保留 dataset-specific mask。
3. 编写一页 dataset card，记录来源、任务、样本量口径、动作语义和已知限制。
4. 设计 mixture sampling：按轨迹数、按数据集均衡或温度采样，并解释取舍。

## 6. 作业输入、预期输出与验证方法

| 项目 | 内容 |
|---|---|
| 输入 | 本体 A：单相机、10 Hz、基坐标系 7D delta pose；本体 B：双相机、20 Hz、关节速度 6D + gripper。 |
| 预期输出 | dataset card 不虚构真实数据事实；对于 mock 明确标注“虚拟样例”；混合方案能说明数据量与任务多样性的权衡。 |
| 验证方法 | 检查每个动作字段都有单位与 frame。；检查样本量是 episode、step 还是小时。；检查 mixture 权重和为 1。 |

预期输出只有在实际运行并保留证据后才能改写为“实测通过”。

## 8. 评分与验收标准

| 评分项 | 分值 | 得分条件 |
|---|---:|---|
| 概念、公式与形状 | 20 | 定义准确，变量、单位和 shape 可追踪 |
| 实现或结构化产物 | 25 | 文件完整，输入输出契约明确 |
| 验证证据 | 25 | 有命令/手算、断言、实际输出或诚实的“预期”标记 |
| VLA 场景分析 | 20 | 能联系闭环、数据或动作风险，而非复述定义 |
| 复盘与自测 | 10 | 解释失败原因并正确回答自测 |
| **总分** | **100** | **80 分通过** |

硬门槛：未定义动作语义就提出拼接训练，或把 mock 数字表述为 OXE 实际统计，不得通过。

## 9. 常见错误与排查提示

- 只对齐维度，不对齐含义。
- 忽略不同控制频率导致的动作幅值差。
- dataset card 没有许可/来源字段。
- 若输出与预期不符，先打印 episode/step 索引、shape、dtype、单位和 dataset key，再检查模型。
- 不得把论文中的报告结果或本页“预期输出”写成本地实测。
