## 1. 今日目标与预计时间

预计 2–3 小时。用完全一致的训练/评估协议比较 `state → action` 与 `image + state → action`，交付曲线、成功率、模态证据和失败复盘。

## 2. 这在 VLA 中的作用

加入语言前必须确认视觉真的提供了目标信息。严格 baseline 能揭示 state 是否泄漏目标、图像是否被模型忽略，以及视觉编码成本是否带来闭环收益。

## 3. 核心概念、公式与比较框架

公平对照保持：episode split、seed、训练步数、动作 loss、normalization 和 rollout seeds 相同，只改变视觉输入。比较表至少包含参数量、训练耗时、test MAE、夹爪准确率、成功数/总数。

模态依赖检查：

```text
正常图像
图像置零/打乱
正常 state
state 置零/打乱
```

若图像打乱后成功率不变，应优先怀疑数据泄漏或模型忽略视觉。

## 4. 分步学习

1. 冻结评估协议和两个模型配置，只保留必要差异。
2. 从头或载入可复现 checkpoint，收集同尺度曲线。
3. 对两模型执行同一组至少 10 个低资源或 20 个主路径 rollout。
4. 对视觉模型做图像置零/跨 episode 打乱测试。
5. 选 3 个失败 episode，按感知、状态、控制、数据或判定器分类。
6. 闭卷完成本周测验，并写下第 7 周加入语言前的接口冻结项。

## 5. 必做作业

- 提交两个 baseline 的配置、checkpoint 标识和训练/验证曲线。
- 提交公平对照表及 rollout 原始逐 episode 记录。
- 提交视觉模态消融与失败案例；明确结果是实际运行还是未执行预期，不得补造数值。

## 6. 输入、预期输出与验证

输入：同一 train/val/test split、相同 normalization、两个模型、固定评估 seed 列表。

预期输出：形成可解释的对照。目标依赖像素而 state 不含目标时，视觉模型理论上应更有优势；若实际不成立，应报告并分析，而不是修改结果。

验证：脚本检查配置除模型输入外关键字段一致；重载 checkpoint 重跑至少 1 个 seed；成功率从逐 episode CSV/JSON 重新汇总；消融不改变 state/action 预处理。

## 7. 固定提交格式

```markdown

- 实际用时与设备：
## 数据切分和公平协议
## 两模型结构/配置

## 图像置零/打乱消融
## 三个失败案例
## 周测答案与下周接口冻结项
```

## 8. 评分与验收

- 对照协议公平且可追溯：20 分。
- 两模型有真实曲线/checkpoint 证据：20 分。
- 离线与 rollout 指标完整：20 分。
- 模态消融能检验视觉依赖：20 分。
- 失败复盘、周测和复跑：20 分。

总分 100，80 分通过；episode 泄漏、挑选评估 seed、没有视觉依赖测试或只报最佳单次结果时不通过。

## 9. 常见错误与排查

| 错误 | 排查 |
|---|---|
| state-only 也近乎完美 | 检查 state 是否包含 object/goal pose 泄漏 |
| visual 模型明显更差 | 先查预处理、encoder 梯度、数据量和训练步数 |
| 打乱图像仍不变 | 检查融合连通、目标泄漏和任务是否真的需要视觉 |
| 两模型不可比 | 固定 split、seed、loss、步数和评估 episodes |

## 10. 时间不足时的最低完成线

用 CPU synthetic 数据训练两个 tiny 模型；各做 10 次 Mock rollout；完成图像打乱消融和 1 个失败案例。保留所有实际日志。

## 11. 可选提高

增加 image-only baseline；比较 frozen 与 fine-tune；用配对 bootstrap 估计成功率差异。

## 12. 完成后的自测题

1. 什么证据能说明模型使用了视觉，但尚不能说明正确 grounding？
2. state 泄漏目标位置会怎样扭曲结论？
3. 公平 baseline 至少要固定哪些变量？
4. 为什么下周加入语言时仍应保留本周模型？
5. 你会优先修复哪个失败类别，证据是什么？
